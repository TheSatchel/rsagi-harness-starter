# 紧凑角色控制协议 v0.3.0

模型输出移动意图、视线变化和准星交互，原版客户端负责物理、碰撞和操作。普通移动不需要逐个列出键盘按键。

SDK 校验器、机械转换器及主办方侧的真实客户端执行代码已经按本协议编写；完整在线画面—模型—同步服务器闭环尚未验收。本文件及 Mock 测试不能作为正式可开赛的证明。

## 最小输出

```json
{"action":{"vel":[1,0,0]},"why":"树在前方，先接近。"}
```

```json
{"action":{"vel":[1,0,0.25],"do":"mine","ticks":20},"why":"边向前右转边采集准星处的木头。"}
```

`why` 是可见依据和动作目的的一句简短说明，最长 300 个字符，计入输出 token。无需输出内部思维链；原有三字段 `explanation` 仍可使用，一次输出只用其中一种说明格式。`harness_update` 只在有修订时输出。

## 参数

普通动作不带 `type`，所有字段都可省略。旧的 `INPUT/keys/look_delta` 格式在 v0.3.0 明确拒绝。

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `vel:[前后,左右,旋转]` | 三维均为 −1..1，正数为前进、右移、右转，负数反向。移动方向相对于角色当时朝向，前两维向量长度超过 1 时归一化；旋转独立计算 | `[0,0,0]` |
| `look:[水平,俯仰]` | 可选的一次性相对角度，单位度；正数为右转、低头，负数为左转、抬头。水平增量 ±180、俯仰增量 ±90；最终俯仰按原版限制 | `[0,0]` |
| `do` | `none / mine / attack / use / hold_use`，见下表 | `none` |
| `ticks` | 本次输入持续的逻辑游戏 tick，1..80；每轮推进 5 tick | `5` |
| `slot` | 选择快捷栏第 1..9 格，与玩家数字键一致 | 保留当前选择 |
| `mode` | `walk / sprint / sneak`，实际速度受原版饥饿、药水、地形和碰撞限制 | `walk` |
| `jump` | 额外显式跳跃/上浮输入，供自动跳跃覆盖不了的动作使用 | `false` |

第三维 `vel[2] = 1` 表示每逻辑秒右转 180°，即每原生 tick 右转 9°；`-1` 反向。默认五 tick 内总共转 45°，`0.25` 在持续 20 tick 时总共右转 45°。转向与本次输入一起到期；不会按现实推理时间继续旋转。

`look` 在动作开始时只应用一次，随后执行 `vel` 的持续旋转；不需要一次性瞄准时可完全省略。模型无需输出四元数。SDK 的 `view_quaternion(yaw,pitch)` 可将无翻滚朝向转成 `[w,x,y,z]`，并固定 q/−q 的符号半球；这只是朝向运算，不是世界信息接口。

`vel` 是角色局部的移动输入强度，不是以方块/秒计的刚体速度，不调用服务端 `setVelocity` 或修改角色坐标。真实客户端将输入交给原版物理。

自动跳跃统一默认开启，使用 Minecraft 原版机制，不寻找绕路、选择落点或判断任务，也不能保证越过任意障碍。所有队伍设置一致。API 握手返回 `character_control`，锁定控制规格、自动跳跃、旋转速度和持续时间上限；不一致时 SDK 拒绝接入。

## 准星交互

| `do` | 原版操作 |
| --- | --- |
| `mine` | 按住左键，最长到 `ticks` 用尽；挖掘进度、工具、目标和距离按原版计算 |
| `attack` | 单击一次攻击键；不自动选敌、瞄准或等冷却补第二击 |
| `use` | 单击一次使用键；放置、开箱、开门等由当前手持物、准星与原版规则决定 |
| `hold_use` | 按住使用键，例如拉弓、进食、举盾；到期或新动作时松开 |
| `none` | 不挖掘、攻击或使用 |

不接受方块/实体 ID、世界目标坐标、后台容器内容、`go_to`、`find_tree`、`mine_until_done` 等任务接口。模型自己根据玩家画面判断目标、进度和下一步。

## 持续、积攒和停止

1. 新普通动作完整替换上一份输入。省略的 `vel` 回到 `[0,0,0]`、省略的 `do` 回到 `none`，不会留下旧按键。
2. `{"action":{},"why":"已经到边缘，停止输入。"}` 撤销旧移动、旋转与交互。惯性、下落、击退仍按原版物理计算，不会把角色强行固定。
3. 模型 `WAIT` 或 Harness 零调用积攒额度，都不创建新动作。仅当上次显式 `ticks` 尚未用尽时继续原操作。
4. `{"vel":[1,0,0],"ticks":20}` 覆盖四轮；随后三轮可积攒额度，原决定继续执行，到期停止。
5. 思考期间模拟不应推进，剩余 tick 不应减少。模型超时、非法输出、公共故障和停赛必须撤销旧输入；不能用失败后的普通 WAIT 无限延长上一动作。
6. 界面、F3、聊天动作先撤销持续输入。每次输出仍只有一份动作，不接收动作序列、条件脚本或自动完成任务。

持续输入的来源、起始轮次、tick 预算与撤销原因应保留在主办方审计。

## 辅助操作

```json
{"action":{"type":"KEY_PRESS","key":"f3"},"why":"打开允许的调试画面确认自身方向。"}
```

```json
{"action":{"type":"GUI_CLICK","x":640,"y":380,"button":"left","shift":false},"why":"点击当前界面中可见的物品。"}
```

`KEY_PRESS` 可用 `f3 / inventory / escape`。界面坐标采用统一 1280×720 玩家画面中的像素，不接受后台容器槽位 ID。`CHAT` 是游戏内普通消息，不接受斜杠指令。

Harness 只请求主办方调用模型并提交原始输出的票据，不自行构造动作。主办方执行器用 `rsagi_harness.control.native_fields()` 做无语义字段转换，原始简短输出保留在审计中。
